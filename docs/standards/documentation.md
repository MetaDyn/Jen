# Documentation Standards

## Purpose

This repository should become the authoritative internal reference for how MetaDyn's orchestration, infrastructure, immersive platforms, and AI systems are described.

## Principles

- Prefer clear structure over giant catch-all notes.
- Capture architecture decisions in writing.
- Separate high-level concepts from runbooks.
- Keep secrets out of version control.
- Update docs when systems change.
- Prefer curated durable documentation over transient chat context.

## Recommended Categories

- architecture
- infrastructure
- platforms
- ai-systems
- runbooks
- standards

## Writing Style

- concise but explicit
- technical where needed
- avoid marketing fluff in internal docs
- record assumptions and open questions
- document boundaries and ownership

## Security

Never commit:
- private keys
- credentials
- access tokens
- raw secrets
- sensitive customer data
- unsanitized infrastructure dumps
