# MetaDyn Projects

This section is the working project memory for active client, partner, platform, and internal build efforts.

Purpose:
- keep project-specific context organized in one place
- reduce repeated ramp-up in conversation
- separate project details from broader company/platform docs
- give Jen a stable place to accumulate status, decisions, constraints, links, and next actions

## How to use this section

Each project should have its own folder under `docs/projects/`.

Recommended contents:
- `README.md` — the main project snapshot
- optional supporting docs as needed for plans, technical notes, outreach notes, deployment details, assets, or meeting summaries

## Standard project snapshot format

Each project `README.md` should try to answer:
- What is this project?
- Why does it matter?
- Current status
- Active threads
- Key decisions
- Constraints / requirements
- Open questions
- Next actions
- Important links / repos / environments
